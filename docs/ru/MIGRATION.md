# Руководство по миграции (v1 -> v2)

Версия 2.0 представляет собой полную переработку библиотеки и узлов Node-RED.
Основное изменение — **отказ от SSH в пользу HTTP API**.

## Библиотека (`padavan`)

### Изменения в конструкторе

Конфигурация теперь передается в виде вложенного объекта `credentials`, а не
плоским списком.

**v1.x (Старый):**

```javascript
const client = new Padavan({
    host: '192.168.1.1',
    username: 'admin',
    password: 'password'
});
```

**v2.x (Новый):**

```javascript
const client = new Padavan({
    credentials: {
        host: '192.168.1.1',
        username: 'admin',
        password: 'password'
    },
    logLevel: 'error'
});
```

### Изменения в структуре данных

- **History (История)**:
  - **v1**: Возвращал `{ daily_history: [], monthly_history: [] }`. Массивы
    содержали сырые данные.
  - **v2**: Возвращает `{ daily: [], monthly: [] }`. Ключи переименованы. Даты
    автоматически парсятся в объекты `Date` и строки `dateStr`.
- **Changelog (Список изменений)**:
  - **v1**: Возвращал `{ from_id, to_id, data: [...] }`.
  - **v2**: Возвращает `{ from, to, messages: [...] }`. Ключи `from_id`/`to_id`
    переименованы в `from`/`to`, а `data` в `messages`.
- **Devices (Устройства)**:
  - **v1**: Возвращал `{ hostname, ip, mac, rssi }`.
  - **v2**: Возвращает `{ mac, ip, hostname, type, rssi }`. Добавлено поле
    `type` (`eth`, `wifi`, `2.4GHz`, `5GHz`).

### Удаленные методы

- **`startSpeedTest()`**: Удален.

### Измененные методы

- **`exec(command)`**: Теперь работает через веб-интерфейс (`SystemCmd`).
  Интерактивные команды не поддерживаются.
- **`getParams()`**: Добавлено кратковременное кэширование (3 секунды) для
  оптимизации производительности при одновременных запросах.

## Node-RED (`node-red-contrib-padavan`)

### Удаленные узлы

- **SpeedTest**: Узел полностью удален из пакета.

### Изменения в конфигурации (`padavan-config`)

- Поля настройки остались прежними.
- Логика подключения изменена с SSH на HTTP.

### Изменения в узле System (`padavan-system`)

- Добавлены новые действия: `Scan Wi-Fi` и `Wi-Fi Doctor`.

### Изменения в узле Devices (`padavan-devices`)

- **Новая возможность**: Узел теперь сам вычисляет изменения в списке.
  - `msg.changes.hasChanges` (boolean): `true`, если список изменился.
  - `msg.changes.added`/`removed`/`changed`: Массивы затронутых устройств.

### Изменения в узле Params (`padavan-params`)

- **Новые опции**: Узел теперь поддерживает дополнительные параметры для
  действий `set` и `get`:
  - `Режим действия`: Управление применением настроек (например, просто
    применить, перезагрузить, добавить в список).
  - `Service ID`: Указание сервисов для перезапуска.
  - `Group ID`: Обязателен для действий `Add` или `Del` при работе со
    списками.
  - `Скрипт`: Имя скрипта для выполнения.
  - `ASP Страница`: Указание контекста страницы. Полезно для парсинга HTML в
    `get` или автоматического определения Service ID в `set`.

### Изменения в узле Upgrade (`padavan-upgrade`)

- **Критическое изменение**: Структура `msg.payload` изменилась.
  - **v1**: `{ from_id, to_id, data: [...] }`
  - **v2**: `{ from, to, messages: [...] }`

### Изменения в узле History (`padavan-history`)

- **Критическое изменение**: Структура `msg.payload` изменилась.
  - **v1**: `{ daily_history: [...], monthly_history: [...] }`
  - **v2**: `{ daily: [...], monthly: [...] }`
- Поля `msg.networkUsage` и `msg.networkUsageMB` сохранены, но логика расчета
  улучшена: теперь используется статистика за день, если данные за месяц
  отсутствуют.
